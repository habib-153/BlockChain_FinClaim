## Deviations from the phase doc (logged per `CLAUDE.md` §6.2)

- **Tailwind v4, not v3.** `create-next-app@latest` now scaffolds Tailwind v4, which configures via CSS `@theme` blocks in `globals.css` instead of `tailwind.config.ts` (no such file exists in v4). The brand palette (`navy-950/900`, `teal-900/700`, `emerald-500`, `amber-600`, `brick-500`) is wired as `--color-finclaim-*` tokens there — same effect the phase doc asked for (named theme colors, no hardcoded hexes in components), different mechanism.
- **shadcn CLI is on a newer major version** than the phase doc's commands assumed (prompts for a `radix`/`base`/`aria` primitive library and a style preset). Used `-b radix -p nova`; the generated primitives are the same shadcn/ui components (`button`, `card`, `table`, `badge`, `dialog`, `input`, `label`, `tabs`, `textarea`, `avatar`, `separator`, `sonner`, plus `select`, `dropdown-menu`, `sheet`, `skeleton` for the shell/forms/dialogs). The `checkbox` component (needed for the flag-clearing two-step) is hand-written in the same style — `ui.shadcn.com` was unreachable for that one `add` call in this sandbox, but the underlying `radix-ui` package was already installed, so it's a straight port of the standard shadcn checkbox.
- **No `next/font/google`.** Turbopack's font loader couldn't resolve `fonts.gstatic.com` in this sandbox and failed the build. Switched to a native system-sans stack in `globals.css`'s `--font-sans`, which the phase doc §2 already allowed ("a clean system/sans stack (e.g. Inter, already shadcn's default)").
- **State management uses `useSyncExternalStore`, not `useState`+`useEffect`.** The naive "hydrate from `localStorage` in a `useEffect`" pattern is flagged as an error by the `react-hooks/set-state-in-effect` ESLint rule bundled with this Next.js version, and — more importantly — it caused a real bug: hard-reloading a nested protected route (e.g. `/regulator/flags`) briefly saw a null session before the effect corrected it, bounced through `/login`, and landed on the role's *root* dashboard instead of staying put. Fixed by making the session's "not yet resolved" state (`undefined`) explicitly distinct from "logged out" (`null`) in `session-store.ts`, and gating `RoleGuard`/`/login`/`/`'s redirect effects on that. Verified fixed with a headless-browser hard-navigation test.
- **Extra plumbing beyond the phase doc's exact file list**: `lib/{session-context,session-store,data-context,app-data-store,capacity,ids}.ts` and `hooks/useAppData.ts`. The phase doc's folder sketch only named `hooks/useSession.ts`, but the live submit→attest / submit-claim / clear-flag / freeze flows need shared mutable state beyond the read-only session — this is that layer, kept in `lib/` as plain modules with a thin React binding, not embedded in components.

The underlying capability (`resetToFixtures` in `lib/app-data-store.ts`, exposed through `AppDataProvider`/`useAppData`) is left in place — nothing calls it from the UI anymore, but it's still there if the team wants to wire it back in behind something judges won't see (e.g. a keyboard shortcut) before presenting.

Re-check any new copy added after this date; nothing enforces this automatically (no lint rule), so it depends on whoever writes the next batch of text noticing the convention.
- **Financing-request direction inverted** (3 Sept, same-day session, direct user instruction) — previously lenders self-served a `Claim` against any `ACTIVE` receivable via `/lender/claims/new`. Now the seller requests a specific amount from a specific bank, either bundled into the receivable submission itself (`SubmitReceivableForm`, now a two-section "invoice + financing request" form) or filed afterward against an already-`ACTIVE` receivable via the repurposed `SubmitClaimForm` (moved to `/seller/financing/new`; `/lender/claims/new` deleted). `ClaimStatus` gained a `"PENDING"` value: a claim bundled at submission time sits `PENDING` until `attestReceivable()` evaluates it right after flipping the receivable to `ACTIVE` — a bank is never told a request is even reviewable against an unconfirmed obligation.
  - **Correction mid-session, direct user instruction**: the first pass over-automated this — `evaluateClaim()` auto-*approved* whenever a request fit within capacity, mirroring the old lender-self-serve behavior. The actual ask was auto-**reject**-only (a request that can't possibly fit is rejected immediately, with the reason shown to the seller) — anything that fits must sit `PENDING` in the target bank's own dashboard for a human to manually **Approve**/**Reject** (new `decideClaim()` in `app-data-store.ts`, wired into `ClaimTable`'s new `onDecide` prop, rendered on `/lender`). `evaluateClaim()` (`capacity.ts`) now only ever returns `PENDING` or `REJECTED`, never `APPROVED`. Approval re-checks remaining capacity **at decision time** (not just at filing time), since another bank's approval could have consumed capacity in between — `decideClaim()` returns `null` (no-op) if approving would now exceed capacity, and the UI surfaces that as an error rather than silently rejecting the claim. Lenders only see a request once its receivable is `ACTIVE` and it has cleared the auto-reject check (`/lender/page.tsx` filters on both).
- **`penaltyFeeBdt` kept as the internal field name** but all user-facing copy changed from "penalty fee" to "flag clearance fee" (`ClearFlagDialog`, `FlagReviewCard`, `RaiseFlagDialog`, admin's Income tab) — reframes the 0.02%-of-invoice fee as FinClaim's own service fee ("company pays FinClaim to remove a flag") rather than a regulatory penalty, matching the new admin-owned ownership of the flag lifecycle. Renaming the field itself was judged not worth the ripple across fixtures/store/components this close to the deadline.
- **Two pre-existing bugs fixed as part of moving freeze/clear-flag off the regulator**: `ClaimTable.tsx`'s freeze-column header was hardcoded to literally say "Regulator" (now "Controls", role-neutral); `setClaimFrozen`'s audit-log detail text was hardcoded to say "...frozen by the regulator." regardless of caller (now takes an `actorName` param, threaded from `useSession()` at each call site, same fix applied to `clearFlag` and the new `raiseFlag`).
