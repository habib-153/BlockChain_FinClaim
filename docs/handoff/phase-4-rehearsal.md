# Phase 4 Handoff — Rehearsal & Submission

**Self-contained.** Read `CLAUDE.md` at the repo root first. Prerequisite: Phases 1–3 done (or deliberately cut short with the gap documented — check `PROJECT_STATUS.md`).

## Goal

Ship a rehearsed, backed-up submission — don't let the deadline be the first full run-through.

## Tasks

1. **Full rehearsal** of the demo script (`docs/prototype-plan.md` §7) end-to-end on the actual built frontend, timed against the guideline's presentation limits (check `BLOCKCHAIN OLYMPIAD BANGLADESH Blockchain Guideline (2).pdf` for the exact time limit and format — a 10-minute pitch with English speech is the pattern used at the Proposal round; confirm the Prototype round's presentation requirements haven't changed).
2. **Record a backup demo video** — a clean screen capture of the clickable frontend running through the flagship scenario, in case live presentation has technical issues.
3. **Final criteria check** — walk through `docs/prototype-plan.md` §6 (grading criteria → feature mapping) and confirm each of the four graded criteria has a specific, pointable moment in either the live demo or the Phase 3 documentation. If any criterion is thin, that's the last thing worth spending remaining time on — not polish elsewhere.
4. **Confirm the mandatory gate story is airtight** — know exactly what to say if a judge asks "does this actually write to a blockchain," based on Phase 2's real outcome. Don't leave this to improvisation.
5. Assemble whatever else the guideline requires alongside the prototype itself (poster board, presentation slides) if those haven't been handled elsewhere — check the guideline PDF for the full submission checklist, not just the prototype-round mandatory gate.
6. **Submit.**

## Reminder

Do not push anything to the shared GitHub remote without the user doing it themselves — that's an explicit standing instruction, not phase-specific.

## When you're done

Update `PROJECT_STATUS.md` to reflect final submission status.
